# PathFinder — ETL

Offline data ingestion pipeline. Run **once** to populate MongoDB Atlas with all reference data the server queries at runtime.

## Setup

```bash
# From server/etl/
python -m venv venv
# Windows:   venv\Scripts\activate
# Mac/Linux: source venv/bin/activate
pip install -r requirements.txt
playwright install chromium      # one-time, only if you later swap script 02 to live scrape
```

Copy `../.env.example` to `../.env` and fill in values, or export in shell:

```bash
export MONGODB_URI="mongodb+srv://..."
export MONGODB_DB="pathfinder"
export OPENAI_API_KEY="sk-..."
# Optional overrides:
# export OPENAI_EMBEDDING_MODEL="text-embedding-3-small"
```

## Pipeline (run in order)

| Step | Script | Purpose | Time |
|------|--------|---------|------|
| 1 | `01_generate_trajectories.py` | Generate ~3000 synthetic SEA dev career trajectories with explicit pivots → `career_trajectories` | ~5 s |
| 2 | `02_scrape_itviec.py` | Load ~20 curated VN job listings → `jobs` (override via `data/itviec_sample.json`) | ~2 s |
| 3 | `03_load_skills_roadmap.py` | Fetch roadmap.sh role roadmaps → `skills` taxonomy | ~30 s |
| 4 | `04_load_courses.py` | Load ~30 curated courses (MongoDB University + Coursera/Udemy/freeCodeCamp) → `courses` | ~2 s |
| 5 | `05_embed_all.py` | Generate 768-d vectors (`text-embedding-3-small` w/ `dimensions=768`; falls back to deterministic hash if quota / rate-limit hit) | ~2–30 min |
| 6 | `06_create_indexes.py` | Create regular indexes + Atlas Vector Search indexes | ~1-2 min |
| 7 | `07_compute_transitions.py` | Pre-compute `skill_transitions` via aggregation `$out` | ~5 s |

Run all sequentially:

```bash
npm run etl:all     # from server/
```

## Step 5 — embeddings & OpenAI quota

OpenAI's `text-embedding-3-small` is cheap (~$0.02 / 1M tokens) and gives 768-dim vectors via the `dimensions` parameter (Matryoshka truncation), which keeps the existing Atlas Vector Search indexes unchanged. If the API rate-limits you (HTTP 429) or the account runs out of credit (`insufficient_quota`), `05_embed_all.py` automatically switches to **deterministic L2-normalized hash vectors** so ETL always finishes. Those vectors are **not semantically meaningful** — they only satisfy index shape for demos. Re-run `05_embed_all.py` later (after quota is restored) to replace them with real embeddings.

Processing order is **courses → jobs → skills** so the smaller collections get API calls first when quota is tight.

To skip the API entirely (CI / offline): `set EMBED_FORCE_DETERMINISTIC=1` (Windows) before running step 5.

### Switching embedding provider — re-embed all docs

The embedding space of OpenAI is **not interchangeable** with Gemini (or any other provider). If you are migrating an existing database from Gemini-era vectors, run step 5 with the wipe flag once so all `description_embedding` fields get regenerated by OpenAI:

```powershell
$env:WIPE_EXISTING_EMBEDDINGS = "1"
python 05_embed_all.py
Remove-Item Env:\WIPE_EXISTING_EMBEDDINGS
```

The Atlas Vector Search index does not need to be rebuilt — dimension and similarity (cosine, 768) stay the same.

## Why synthetic data for step 1?

The Stack Overflow Developer Survey ZIP is hosted on a rotating Sanity CDN with
hashed paths; the old static URLs (`insights.stackoverflow.com/datasets/...`)
return 403/404. More importantly, SO publishes one **independent cross-section
per year** (no respondent IDs across years), so true career *trajectories*
would have to be inferred via weak cohort matching anyway.

`01_generate_trajectories.py` therefore generates ~3000 anonymised SEA developer
trajectories with **explicit** pivot events, calibrated to plausible 2025-2026
Vietnam market salaries and skill stacks. Properties:

- **Deterministic** — `SEED = 42`, same output every run
- **Rich pivots** — ~62% of profiles have at least 1 pivot, ~15% have 2 pivots
- **Statistically sane** — role mix, salary by seniority/role/country, and
  skill co-occurrence are all calibrated to real market signal
- **No external dependencies** — runs offline

To swap in real SO data later, drop the extracted CSVs in `data/raw/` and write
an adapter that emits documents matching the `CareerTrajectoryDoc` Zod schema
(see `server/src/schemas/trajectory.ts`).

## Re-runs

All scripts are idempotent for the ones that own a collection (they `drop()`
then `insert_many()`):

- `01_generate_trajectories.py` — replaces `career_trajectories`
- `02_scrape_itviec.py` — replaces `jobs`
- `03_load_skills_roadmap.py` — replaces `skills`
- `04_load_courses.py` — replaces `courses`
- `07_compute_transitions.py` — uses `$out` → replaces `skill_transitions`

`05_embed_all.py` is idempotent at the doc level (skips docs that already have
`description_embedding`), so re-running after adding new courses or jobs only
re-embeds the new ones.

`06_create_indexes.py` is idempotent against existing indexes — re-running is
safe.
